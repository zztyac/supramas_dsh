# Agent Note：SupraMAS 全文证据与审查策略

Status: implemented

[English](2026-09-01-supramas-full-text-review-policy.md) | 中文

## Problem

Codex 原生 SupraMAS 流程与 DSH 的首次同输入对比中，DSH 生成了结构合法但科学质量明显更弱的策略树。该会话使用 standard preset，没有成功导入 PDF，通过旧变更工具保存检索摘要，并且所有候选都未经历修订就被接受。领域层只能核验逐字子串，不能区分摘要元数据与已解析全文；子节点边标签也没有持久记录子论文对父期望的满足程度。

证据与工作流状态会跨进程重启持久化，因此仅加强提示词不足以修复问题。模型仍可能绕过预期导入器，先前接受的摘要工作流也可能在更严格的运行时指引发布后继续恢复或最终完成。

## Decision

把全文溯源作为产品状态持久化。每个证据块带有 `evidence_kind: abstract|full_text`；每次成功的完整导入都会保存规范原始 PDF 描述，包含路径、媒体类型、SHA-256、字节数和页数。未提供 evidence kind 时按 `abstract` 处理。存储领域升级到版本 2，旧记录会被拒绝，不会被静默升级成可信全文来源。

当 Stage 1 任务明确排除 `abstract-only evidence` 时，reviewer 接收、持久状态恢复和最终完成都要求每个已接受节点具有有效 `full_text_source`，并且至少引用一个 `full_text` 文本块。兼容导出包含已声明原始 PDF；源文件缺失时导出失败。

Reviewer 输出 schema v2 强制提供 `expectation_satisfaction`。根节点审查使用 `not_applicable`；已接受子节点把 `full`、`partial`、`adjacent` 分别映射为 `direct`、`transferable`、`exploratory`；`none` 不得接受。领域层会在恢复和最终完成时根据已接受审查日志重新校验该关系。

Builder 与 reviewer 的委派改为原子操作。在内置 preset 中，面向 coordinator 的提交工具只接受 `run_id` 与 `revision`。每个工具启动一个深度为一、输出 schema 封闭且使用角色专属工具白名单的子智能体，再把其精确结构化结果与子任务运行 ID 一并提交。模型编排工作流会在提交、恢复和最终完成时强制要求这些运行 ID。`accept` 审查的关键问题、边问题和接收条件必须全部为空；仍有待办时 reviewer 必须返回 `revise` 或 `reject`。

对失败交接设置边界并保持 fail closed。Builder 会收到可复用已导入全文论文的精简目录；目录非空时不再获得检索与导入权限。每个 builder 或 reviewer 子任务默认最多运行十分钟。子任务失败不会修改持久 revision 或尝试计数，随后按运行、revision 和角色在当前进程锁定，使 coordinator 的重复调用直接返回停止信封，不再启动更多子任务。新进程可以从未变化的 revision 恢复并再尝试一次。

移除模型侧旧论文写入、手工文本块提取和整篇产物读取工具。Builder 通过有界检索发现候选，把摘要仅作为发现元数据，并在提交节点前通过专用导入流水线导入完整 PDF。导入失败时只允许改选开放获取候选或细化检索，绝不允许回退到摘要。SupraMAS bundle 不再全局挂载模型工具，浏览器也只会把编排任务加入使用 `supramas` preset 的会话。

公共学术跨源重定向只有在每一跳都独立校验并固定地址后才允许。重定向跳数、私有地址、凭据、流式字节上限和最终 PDF 校验仍然是强制条件。

## Alternatives considered

**只加强 agent 提示词。** 拒绝，因为失败运行已经证明 standard agent 可以调用全局旧工具，并在预期角色指引之外自行接受摘要证据。

**保留旧变更工具但用角色过滤隐藏。** 拒绝，因为 bundle 全局组合或 preset 选择错误仍会产生绕过面。证据创建权限只属于已验证导入器。

**从 reviewer 自由文本推断边类型。** 拒绝，因为自由文本不是可持久、可机器校验的状态，重启后无法可靠复验。

**让 coordinator 调用通用 builder 与 reviewer 工具。** 拒绝，因为同输入实跑显示 coordinator 会修复格式错误的 reviewer JSON，并考虑自行接收。原子结构化委派把子结果、子任务身份和状态转换合并为一个可审计操作。

**拒绝所有跨源重定向。** 拒绝，因为合法开放获取 PDF 经常跳转到公共仓库或 CDN；逐跳公网校验可在不削弱 SSRF 防护的前提下保留这些来源。

**假定旧记录中的文本块都是全文并自动迁移。** 拒绝，因为历史记录没有足够证据证明该来源。fail-closed 版本升级是唯一可靠方案。

## Consequences

摘要候选不能再进入或跨重启存活于受保护的 Stage 1 工作流，边语义在接收、重启和最终完成阶段保持确定。模型可见工具面更小，不再暴露通用角色工具，UI 会在加入任务前发现 preset 错误。每个已接受的模型编排交接都可归属到一个子任务运行，矛盾的接收决策会被拒绝。成功导出现在同时包含可审计原始 PDF、论文 JSON 和最终成果。

已导入全文现在可以作为后续子任务复用的工作成果，而不是一次性会话上下文。Provider 失败或结构化输出错误不会再导致同一 revision 在一个进程中无限创建子任务；运维人员会收到精确且安全的恢复 revision。

旧 SupraMAS 持久记录需要使用领域版本 2 新建运行。部分开放获取候选仍可能因为没有公共 PDF 或文档格式不支持而导入失败；builder 必须继续检索，不能伪造证据。科学质量仍依赖 reviewer 判断，但运行时策略已经封堵本次观察到的两类结构性绕过。
