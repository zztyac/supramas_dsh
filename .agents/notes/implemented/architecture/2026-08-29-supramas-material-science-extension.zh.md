# Agent Note: SupraMAS material-science extension seam

Status: implemented

[English](2026-08-29-supramas-material-science-extension.md) | 中文

## Problem

SupraMAS 需要把材料科学多智能体工作流迁移到 DSH，同时继续跟进 DSH 上游更新。如果把领域状态、角色权限或工作流转换写入 DSH 智能体循环， 该循环就会成为长期分叉。如果只把原 Codex 编排保留为提示词，运行标识、 生命周期转换和工具权限就无法独立验证。

因此，在证据持久化、科学数据结构、恢复机制和 UI 开发开始之前，首个 迁移里程碑必须先建立稳定的扩展边界。

## Decision

SupraMAS 以 DSH 插件、Profile Bundle 和可选择的智能体预设实现。DSH 智能体循环、会话模型、加载器和子智能体驱动保持不变。能力包负责材料 科学运行状态和权限，纯领域包负责 Stage 1 schema 与证据语义，面向模型的 适配器只暴露窄工具；后续持久化、API 和 UI 包都依赖这些边界。

Profile Bundle 先组合能力运行时，再组合工具消费者。内置 `supramas` 预设选择该 Bundle，并提供面向角色的指令，但不会把全部工具授予每个 角色。

## M1 boundary

M1 建立确定性运行标识、比较并交换版本、封闭生命周期图、四个 Stage 0/1 角色契约、创建和读取工具，以及真实 Loader 组合。状态暂存于进程内， 以便在引入持久化存储之前先证明契约。工具错误信封始终包含可执行的重试 方式和停止条件。

## Alternatives considered

**围绕原 SupraMAS 协调器分叉 DSH 智能体循环。** 这样可以更直接地完成 首个演示，但上游每次修改循环、会话或子智能体都需要手工合并，而且会把 科学工作流策略写入通用执行核心。

**只用 Persona 和提示词表示迁移。** 这样能保持上游源码不变，但无法 强制角色专属工具权限、比较并交换状态变更或可机器测试的生命周期规则。 提示词仍属于预设，但不拥有运行时契约。

**在 M1 引入持久化存储。** 重启恢复最终需要持久化，但在运行和角色契约 得到证明之前选择存储结构，会把两个决策过早耦合。M1 有意保留进程内 注册表；M3 的持久化实现会替换 `ctx.supramas` 后面的存储。

## Consequences

- 材料科学行为不分叉核心循环，因此后续仍可合并上游 DSH 更新。
- 角色工具列表是可执行的权限边界，而不是提示性文字。
- 持久化恢复可以在不修改模型工具的情况下替换 `ctx.supramas` 背后的存储。
- 内置 SupraMAS 预设可以独立于普通编码预设演进。
- M1 的运行状态会在进程重启时丢失；在 M3 提供持久化和恢复前，调用方会 明确看到这一限制。

## Validation

每个里程碑先编写失败的契约测试。只有聚焦测试、真实组合冒烟、包类型检查 和相关仓库门禁全部通过后，才进入下一阶段。
